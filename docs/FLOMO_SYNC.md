# flomo 账号缓存与双向同步（1.3.1 候选）

## 使用方式

flomo 笔记同步到现有 CloudBase 的独立账号库，不连接官方 flomo 账号。正文、标签、置顶、回收站、附件数量和永久删除标记参与同步；图片文件、草稿和外观留在原设备。

已启用过 flomo 的账号登录后，主列表统一查看和编辑该账号在这台电脑的缓存；首次启用前仍可编辑原本机笔记。开启同步后，这份缓存与同UID的云端库双向交换：办公室新增并同步后，家中电脑或手机同步会接收同一条笔记。暂停同步只停止网络交换，仍编辑这份账号缓存；恢复后继续交换暂停期间的修改。

首次开启时，没有原本机笔记便直接开启并同步；有笔记则展示目标账号和待加入数量，确认后合并并立即交换。原记录保留为只读归档，不在后续开启、查看或账号切换时重复加入。归档预览、导出及经过预览的合并恢复放在“本机备份与归档”，不作为另一份日常编辑库。账号切换不复制前一账号记录。真正需要重新登录时保留缓存和草稿；未登录时仍可使用本机记录。

## 开关与结果

flomo 同步开关按账号、设备持久保存。明确关闭的 `false` 优先于“账号缓存存在”这类旧版推断；重启、刷新或重新打开账号都不能自行恢复同步。已有账号缓存继续保留，恢复同步无需再次导入原本机归档。

手动同步与前台约12分钟检查保持不变，不新增高频或后台常驻调度。日程／日课／周计划、专注记录、flomo 分别显示结果；专注仍复用 workspace 协议，展示上单独报告。某一类失败不应使其他类的结果被误标或隐藏。flomo 状态说明当前账号、缓存数量、是否暂停、待同步／差异、最近交换与接收情况；云端交换成功不能掩盖交换过程中产生的新修改。

## 差异与重试

相同内容的字段／集合顺序不会产生待同步状态。不同设备创建同路径的新标签会核对身份；只有时间戳不同的相同修改不要求选择。云端提交版本变化时最多追加两次合并提交，持续变化保留待上传内容供重试。

真正的差异按笔记或标签展示本机与云端内容，包含标签、置顶和删除状态。选择只改变当前项；其他无冲突内容继续交换。笔记可采用本机、云端或两个版本都保存，标签可选择一端；涉及关联标签且选择会形成无效层级时先处理关联项。内容在预览后变化时需要重新查看。

已发送请求落盘后保持不可变，丢失确认时重试同一操作；交换期间的后续编辑保留待同步。临时账号服务错误不清除登录。插件通信错误才显示“重试连接插件”，该操作不重放保存、删除或恢复请求。

页面与 worker 的 flomo 消息保持兼容；旧页面需刷新才能使用新界面。不能因旧消息字段缺失把账号库错误命名为 `undefined`。发现历史 `undefined` 等归属不明的库时保留原始数据并提示核查，不删除、不自动并入当前账号、不直接上传。

## 本机备份

“本机备份与归档”支持手动创建、历史列表、预览、导出 JSON 和合并恢复。首次合并、导入、差异选择及恢复前自动备份。自动备份保留最近30份，手动备份单独保留；历史恢复副本单独收纳，时间未知时明确标注。备份按账号隔离，保存本机图片，不包含认证会话。JSON 导出不包含图片文件。

恢复保留备份中没有的当前记录，对同ID不同内容逐条选择；恢复前检查预览版本，避免覆盖其间的新编辑。永久删除标记不会被旧备份复活。

设备迁移保留笔记内容、账号缓存和既有待同步数据，但在目标设备重置 flomo 同步开关，需在该设备明确开启；不会因缓存存在而自动上传。认证会话不迁移。专注记录既有的历史／认领日志保留、来源设备标识重置与独立开关规则不变，见 [专注记录同步](FOCUS_SYNC.md)。

## 维护与验收

核心源码由 D:/tab-out/shared 维护，仅通过既有清单同步 flomo.js、flomo-sync.js、flomo-transport.js；认证源码在各项目分别修复，不跨项目覆盖。小程序使用 node scripts/build-shared.mjs --target=miniprogram，正式桌面仍在独立仓库运行 npm run build。

本轮无需 CloudBase API、数据库结构或后端部署；已部署的专注能力保持原状。两端源码独立，更新Git不会更新已安装客户端。桌面构建、62项测试、最终ZIP隔离Chrome及小程序完整测试、原生编译和最终预览通过，具体证据见 [验收记录](ACCEPTANCE.md)。用户需在扩展管理页重新加载当前扩展，并刷新旧标签页；手机需打开本轮预览。两端同UID真实账号往返仍待验收，合成服务器与隔离Chrome的结果不能替代手机实测。
