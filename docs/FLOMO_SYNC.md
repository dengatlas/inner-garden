# flomo 账号同步

日程与已经开启的flomo账号笔记由同一个“立即同步”或自动同步触发，分别显示结果。一类失败不影响另一类；两类仍使用独立协议。自动模式只在页面可见时约每12分钟检查，手动同步随时可用。

首次启用会确认是否把原本机记录合并到当前账号，原库保留，其他账号内容不复制。已有账号库跟随登录切换；查看启用前本机记录时只在本机编辑。正文、标签、置顶与回收站进入现有flomo服务，图片、草稿和外观仍在原设备。

状态区分本机保存、待同步、已同步和冲突，并显示最近交换收到的新增/更新笔记数。同步期间仍有新编辑时保持待同步提示。处理冲突后需再次同步。

共享合同仅有flomo.js、flomo-sync.js与flomo-transport.js。源合同由小程序仓库维护，按明确清单同步后在本仓库构建；docs/flomo-contract.json记录内容摘要，npm run check检查漂移。认证客户端和prompt种子继续独立维护。

本轮客户端改动不需要部署flomo后端。自动化与合成服务器联调不能替代真实账号、手机和发布版本验收。

本轮检查及38项测试通过；实际Chrome加载ZIP内容，验证本机保存、合成云端接收条数、日程失败时flomo继续、列表收到更新后保留新笔记输入及行内编辑的草稿/焦点/光标。小程序574项测试和原生WXML/WXSS编译通过，真实适配器的合成服务器往返覆盖新增、编辑及软删除。未读取用户的云端笔记，未验证已安装手机版本，未提交或部署。

维护时在本仓库单独提交插件改动，在D:\tab-out单独提交小程序和合同改动。两个提交完成后还需重新加载插件、更新手机小程序；Git提交不会自动更新运行中的客户端。手机仍缺少笔记时，查看flomo单独的接收数和“查看全部笔记”，并核对实际UID、运行版本以及电脑账号库是否仍显示待同步。
